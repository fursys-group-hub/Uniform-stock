## 🔍 깊게 보기 ① "지금 재고 몇 개"는 어떻게 나올까? (비전공자용 쉬운 설명)

재고현황에 뜨는 "현재고 32개" 같은 숫자. 이게 어디서 나오는지 풀어볼게요.

### 1. 한 줄 요약
현재고는 **어딘가에 적어둔 숫자가 아니에요.** 처음 수량에서 그동안의 입고·출고 기록을 **그때그때 더하고 빼서 자동으로 계산**한 결과예요.

### 2. 왜 이렇게 했을까? (핵심 오해 풀기)
"현재고 32"라는 숫자를 칸에 직접 적어두는 방식도 있어요. 하지만 그건 위험해요.

❌ **숫자를 직접 적어두는 방식** — 입출고할 때마다 사람이 32→30→35로 고쳐 적어야 함. 한 번 실수하면 **계속 틀린 채로** 굴러감.

✅ **우리 방식(자동 계산)** — 현재고 칸은 없음. 대신 "입고 +10, 분출 -3…" 기록만 쌓고, 화면에 보여줄 때 **합산해서** 보여줌. 기록이 맞으면 숫자는 **항상 저절로 맞음.**

> **비유:** 통장 잔액을 수첩에 직접 적어두는 것(❌)과, 입금·출금 내역만 두고 잔액은 은행이 자동 계산해 보여주는 것(✅)의 차이예요.

### 3. 전체 흐름 (그림)

```
① 품목의 처음 수량 (기초재고)   예: 30
        │
        ▼
② 그동안의 수불 기록을 하나씩 반영
        │   입고 +10  →  40
        │   분출 -3   →  37
        │   반납 +2   →  39
        │   잉여출고   →  변화 없음(0)
        ▼
③ 화면에 보여줄 때 최종 합계 = 현재고 39 ✅
   (따로 저장 안 함 — 볼 때마다 다시 계산)
```

### 4. 코드에서는 어디서 (파일별 역할)
| 단계 | 파일 | 하는 일 |
|---|---|---|
| ② 부호 정하기 | `public/app.js` | 입고·반납은 +, 분출은 −, 잉여출고는 0 (`getSignedQuantity`) |
| ③ 합산 | `public/app.js` | 기초재고 + 수불 합계로 현재고 계산 (`getCurrentStock`) |

### 5. 자주 나올 질문 (Q&A)
**Q. 기록이 많아지면 느려지지 않나요?** → MVP 규모(품목 수십 개)에선 문제없이 즉시 계산돼요.
**Q. 잉여출고는 왜 0인가요?** → 나간 사실은 기록하되 재고엔 반영 안 하는 구분이에요. → [6/24 참고](2026-06-24_잉여출고.md)

### 6. 핵심만 다시
- 현재고 = **기초재고 + 수불 기록 합산** (직접 적어두는 숫자가 아님)
- 기록만 맞으면 재고 숫자는 **항상 자동으로 맞음** → 손으로 고치다 틀릴 일이 없음

## 🔍 깊게 보기 ② 단가를 바꾸면 과거 청구금액이 왜 저절로 바뀔까? (소급 반영)

### 1. 한 줄 요약
분출 기록에 금액을 **고정해 박아두지 않고**, 화면에 보여줄 때 **그 품목의 지금 단가 × 수량**으로 계산해서 보여줘요. 그래서 단가를 바꾸면 과거 건도 새 단가로 다시 계산돼요.

### 2. 왜 이렇게 했을까? (핵심 오해 풀기)
❌ **금액을 박아두는 방식** — 분출할 때 "3개 × 5,000 = 15,000" 을 그대로 저장. 나중에 단가가 6,000으로 바뀌어도 과거 건은 **15,000에 멈춰** 정산이 어긋남.

✅ **우리 방식** — 금액을 저장하지 않고, 볼 때 "수량 × 현재 단가"로 계산. 단가를 고치면 과거 청구액도 **자동으로 새 값**이 됨.

> **비유:** 환율을 거래 시점 값으로 종이에 적어두면 나중에 안 맞지만, "달러 수량"만 두고 볼 때마다 오늘 환율로 환산하면 항상 최신이 되는 것과 같아요.

### 3. 전체 흐름 (그림)

```
분출 기록:  품목=안전화, 수량=3     (금액은 저장 안 함)
        │
        ▼
단가표:    안전화 = 5,000원  →  청구액 = 3 × 5,000 = 15,000
        │
   (관리자가 단가를 6,000으로 변경)
        │
        ▼
같은 분출 기록을 다시 볼 때 = 3 × 6,000 = 18,000 ✅  (저절로 갱신)
```

### 4. 자주 나올 질문 (Q&A)
**Q. 과거 거래는 그때 단가로 남겨야 하지 않나요?** → 이 앱은 "현재 단가 기준 정산"이 목적이라 소급 방식을 택했어요. (시점별 단가 고정이 필요하면 그건 별도 설계)

### 5. 핵심만 다시
- 금액은 **저장이 아니라 계산** → 단가 변경이 과거 건까지 자동 반영
- 단가표만 최신으로 유지하면 정산 금액은 **손 안 대도 최신**

## 🤔 고민 과정 (기록용)

- **완성도 vs 속도.** 제대로 된 서버·DB를 갖추려면 시간이 오래 걸리는데, 재고는 지금 당장 매일 움직인다. 그래서 "일단 오늘 쓸 수 있는 것"을 우선해 **파일 하나로 도는 형태**로 시작했다. 데이터는 브라우저(localStorage)에 담았다 — 이게 나중에 유실 문제로 [7/29 대전환](2026-07-29_대전환_회사DB백엔드.md)의 계기가 된다.
- **현재고를 저장할까, 계산할까?** 계산 방식을 택했다. 저장해두면 빠르지만 사람이 고치다 틀리면 계속 틀린다. "기록이 진실, 숫자는 결과"라는 원칙을 처음부터 세운 셈이다.
- **이력을 아무나 고치게 둘 순 없었다.** 오기입 수정은 꼭 필요하지만, 과거 기록을 자유롭게 바꾸면 재고 신뢰가 무너진다. 그래서 수정·삭제에만 비밀번호 잠금을 걸어 "고칠 수는 있되 함부로는 못 하게" 했다.

### 데이터는 어디에? — localStorage 한 곳
서버가 없으니 브라우저 저장소에 통째로 담았다. 상태는 `{ items, transactions, audits }` 한 덩어리.
```js
const STORAGE_KEY = 'inventory_mvp_v1';
function loadState() { return JSON.parse(localStorage.getItem(STORAGE_KEY)) || makeSeedState(); }
function saveState() { localStorage.setItem(STORAGE_KEY, JSON.stringify(state)); }
```

### 현재고 자동 계산 — 저장하지 않고 매번 합산 (`app.js`)
```js
function getSignedQuantity(tx) {
  if (tx.type === '입고' || tx.type === '반납') return tx.quantity;
  if (tx.type === '분출') return -tx.quantity;
  if (tx.type === '잉여출고') return 0;   // 기록만, 재고엔 영향 없음
  return tx.quantity;                      // 재고조정 등
}
function getCurrentStock(itemId) {
  const init = getItemById(itemId)?.initialStock || 0;
  const sum = state.transactions.filter(t => t.itemId === itemId)
                                .reduce((acc, t) => acc + getSignedQuantity(t), 0);
  return init + sum;                        // 기초재고 + 수불 합계
}
```

### 단가 소급 반영 — 단가를 바꾸면 과거 분출 청구액을 다시 계산 (`app.js`)
현재고와 달리 청구금액(`amount`)은 각 거래에 저장돼 있어서, 단가를 바꿀 때 **과거 거래들을 훑어 새 단가로 갱신**한다.
```js
function savePriceInline(...) {
  item.unitPrice = 새단가;
  state.transactions.forEach(tx => {
    if (tx.itemId === itemId) {
      tx.unitPrice = item.unitPrice;
      tx.amount = tx.type === '분출' ? tx.quantity * item.unitPrice : 0;  // 소급 재계산
    }
  });
}
```

### 그 외
- **이력 수정/삭제**: 관리자 비번 확인 후 `state.transactions`에서 편집 → `saveState()`.
- **캐시 방지**: `index.html`에서 `app.js?v=2`, `styles.css?v=2`처럼 버전 쿼리를 붙여 배포 시 갱신 강제.
