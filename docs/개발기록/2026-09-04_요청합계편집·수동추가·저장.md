## 🔍 깊게 보기 — 왜 편집·수동추가가 필요했나 (비전공자용)

### 1. 상황
요청 합계는 **배포 이후 요청** 만 쌓여서, **과거 주문 건은 데이터가 없었음.** 그런데 담당자는 과거 건도 수기로 정리해 슬랙에 보내고 싶었다.

### 2. 그래서 만든 것
- **수량 직접 수정** — 합산된 값을 입력창에서 바로 고침(합계 실시간 반영)
- **수동 행 추가** — 품목·사이즈·수량을 직접 입력해 추가(같은 것 재추가 시 자동 합산)
- **💾 저장** — 그 기간에 맞춰 DB에 저장 → 다음에 같은 기간 조회하면 그대로 복원
- **🔄 요청에서 다시 합산** — 저장/수정 버리고 요청 원본에서 재집계

### 3. 흐름 (그림)
```
과거 기간 조회 → "저장된 요청 없음"
      │
      ▼  수동 추가(조끼 105 · 40) / 수량 편집
      ▼  💾 저장  (DB app_config: reqsum:기간)
      ▼  📨 슬랙 게시
   나중에 같은 기간 다시 조회 → 💾 저장본 자동 복원
```

### 4. 핵심만
- 과거 건도 **직접 채워 보내고**, **저장하면 유지** 됨
- 저장본은 **기간별** 로 보관 → 주간 단위 작업에 딱

## 🤔 고민 과정

- **"과거 건은 어떻게?"** — 소급 저장은 불가능(그땐 저장 안 했으니). 그래서 **수기 입력 + 저장** 이라는 현실적 해법. "지금 채워서 보내고, 남겨두기".
- **편집값을 어디에 저장?** — 요청 원본(`uniform_requests`)을 고치면 안 됨(원본 훼손). 그래서 **합계 결과를 별도(app_config)에** 기간 키로 저장. 원본은 그대로 두고, "이 기간의 준비수량 확정본"만 따로 보관.
- **실시간 반영** — 수량 편집 시 화면을 통째로 다시 그리면 입력 포커스가 튀어서, **모델만 갱신 + 합계 숫자만** 갱신하도록 처리.
