## 🔍 깊게 보기 왜 '재고조정'만 음수를 허용했을까? (비전공자용 쉬운 설명)

### 1. 한 줄 요약
재고를 **줄여야 하는 보정**이 필요해서 음수 입력을 열되, 실수 위험이 큰 다른 구분(입고·분출 등)은 **그대로 양수만** 받게 했어요. 딱 재고조정에서만.

### 2. 왜 이렇게 했을까? (핵심 오해 풀기)
실사하다 보면 장부가 실물보다 많게 잡혀 있어서 **깎아 맞춰야** 할 때가 있어요.

❌ **모든 구분에 음수 허용** — 편하지만, 입고에 실수로 −를 넣는 등 **오입력 위험**이 커짐.
❌ **음수 아예 금지(기존)** — 안전하지만 "줄이는 보정"을 **입력할 방법이 없음.**

✅ **재고조정에서만 음수 허용** — 보정 전용 구분에서만 문을 열어, 필요는 채우고 위험은 막음.

> **비유:** 일반 결제는 취소를 못 하게 막아두고, '환불 전용 창구'에서만 마이너스(환불)를 받는 것과 같아요.

### 3. 전체 흐름 (그림)

```
입력하는 구분에 따라:
   입고 / 분출 / 반납  → 최소 1 (양수만)   ← 오입력 방지
   재고조정            → +/− 모두 허용     ← 양방향 보정
```

### 4. 자주 나올 질문 (Q&A)
**Q. 왜 분출로 줄이면 안 되나요?** → 분출은 '실제 지급' 기록이에요. 단순 수량 보정을 분출로 넣으면 지급 이력이 오염돼요. 그래서 보정은 '재고조정'으로 분리.

### 5. 핵심만 다시
- **재고조정만** 음수 허용 → +/− 양방향 보정
- 위험한 구분은 양수만 → **오입력 차단** 유지

### 핵심 한 줄 — 입력칸의 `min`을 구분에 따라 바꾼다 (`app.js`)
수량 입력칸(`<input type="number">`)의 최소값을, 재고조정일 때만 제한 없이(음수 허용), 나머지는 1로 고정한다.
```js
function syncTransactionAmount() {
  const type = els.transactionForm.type.value;
  // 재고조정만 음수 허용(재고 차감용), 나머지 구분은 최소 1로 제한
  els.transactionForm.quantity.min = (type === '재고조정') ? '' : '1';
  ...
}
```
- `min=''` → 브라우저가 음수 입력을 막지 않음 (재고조정)
- `min='1'` → 1 미만은 입력 불가 (입고·분출·반납 등)
