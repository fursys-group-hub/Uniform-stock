## 🔍 깊게 보기 ① "단가는 왜 시공팀에게 안 보일까?" (비전공자용 쉬운 설명)

시공팀 화면(`/request`)에서는 재고 수량은 보이지만 **단가(가격)는 안 보여요.** 관리자가 비밀번호를 넣으면 그때만 보이죠. 이게 어떤 원리인지 쉽게 풀어볼게요.

### 1. 한 줄 요약
시공팀 화면에는 서버가 **단가를 아예 안 보내줘요.** 그래서 볼 수가 없어요. 관리자가 비밀번호를 넣으면, 그때 서버가 **단가만 따로** 내려줘요.

즉 "화면에서 가려둔 것"이 아니라 **"처음부터 안 준 것"** 이에요. 그래서 진짜로 안전해요.

### 2. 왜 이게 안전할까? (핵심 오해 풀기)
"화면에서 숨기면 되지 않나?" 싶지만, 화면에서만 숨기는 건 안전하지 않아요.

❌ **화면에서 숨기는 방식** — 데이터는 이미 브라우저에 와 있고 화면에만 안 띄운 것. 개발자 도구(F12)로 열면 **그대로 다 보임.**

✅ **우리 방식** — 시공팀 화면에는 서버가 단가를 **애초에 안 보냄.** 브라우저 어디를 뒤져도 단가 자체가 없음.

> **비유:** 금고 열쇠를 "책상 서랍에 넣고 서랍을 닫아두는 것"(❌ 숨기기)과, "열쇠를 아예 다른 방에 두고 필요할 때만 가져오는 것"(✅ 안 주기)의 차이예요. 서랍은 열면 그만이지만, 다른 방에 있으면 가져오지 않는 한 만질 수 없어요.

### 3. 전체 흐름 (그림)

```
[평소 — 시공팀 화면]
① 브라우저: "재고 목록 주세요"
      │
      ▼
② 서버: 재고 목록 전송  ── 단가는 뺀 채로! (품명·사이즈·현재고만)
      │
      ▼
③ 화면: 수량은 보이고, 단가 자리는 아예 없음 ✅

[관리자가 단가를 볼 때]
④ 관리자: 단가 비밀번호 입력
      │
      ▼
⑤ 서버: 비번 맞나 확인 → 맞으면 그때 '단가만' 따로 전송
      │
      ▼
⑥ 화면: 단가 표시 ✅  (비번 틀리면 아무것도 안 옴)
```

### 4. 코드에서는 어디서 일어나나 (파일별 역할)
어려운 코드는 몰라도 돼요. **"어느 파일이 무슨 일을 하는지"** 만 보면 돼요.

| 단계 | 파일 | 하는 일 |
|---|---|---|
| ②③ 단가 빼고 재고만 | `server/server.js` | `/api/stock` — 품명·사이즈·**현재고만** 응답 (단가 없음) |
| ⑤ 비번 확인 후 단가 | `server/server.js` | `/api/prices` — 비밀번호가 맞을 때만 단가 응답 |
| ①④⑥ 화면 표시 | `public/request.html` | 평소엔 단가 없이 표시, 비번 넣으면 단가 요청해서 표시 |

### 5. 자주 나올 질문 (Q&A)
**Q. 시공팀이 개발자 도구로 열어보면 단가가 보이나요?**
→ 안 보여요. 서버가 시공팀 화면엔 단가를 **아예 안 보내서**, 브라우저 어디에도 단가 데이터가 없어요.

**Q. 관리자는 단가를 어떻게 보나요?**
→ 화면에서 단가 비밀번호를 넣으면, 서버가 확인 후 그때만 단가를 내려줘요.

**Q. 비밀번호가 틀리면요?**
→ 서버가 거절해서 아무 단가도 안 와요. (에러 안 나고 그냥 안 보임)

### 6. 핵심만 다시
- 단가는 **화면에서 가린 게 아니라, 서버가 안 보낸 것** → 진짜 안전
- 관리자가 **비번을 넣어야만** 서버가 단가를 따로 내려줌
- 시공팀은 수량만 보고 편하게 요청, 가격 정보는 보호됨

## 🔍 깊게 보기 ② 시공팀이 요청하면, 담당자 슬랙에 어떻게 알림이 뜰까?

시공팀이 유니폼을 장바구니에 담아 "요청"을 누르면, 잠시 뒤 담당자 슬랙에 주문 메시지가 떠요. 이게 어떻게 오는지 풀어볼게요.

### 1. 한 줄 요약
요청을 받은 **서버가, 슬랙에 미리 열어둔 전용 통로(웹훅)** 로 메시지를 대신 쏴줘요. 요청한 시각은 사람이 적지 않고 **서버가 한국시간으로 자동으로** 붙여요.

### 2. 왜 이렇게 했을까? (핵심 오해 풀기)
❌ **전화·개별 메신저 방식** — 요청이 여기저기로 흩어져 와서 누락·중복이 생기고, 나중에 "누가 언제 뭘 요청했는지" 기록이 안 남음.

✅ **우리 방식** — 요청이 **한 창구(슬랙 채널)** 로, **같은 형식**으로 모임. 시각도 서버가 자동으로 찍어 실수가 없음.

> **비유:** 주문을 직원마다 말로 받는 것(❌)과, 모든 주문이 한 장의 주문서 양식으로 주방 모니터에 뜨는 것(✅)의 차이예요.

### 3. 전체 흐름 (그림)

```
① 시공팀: 장바구니에 담고 [요청] 클릭
        │   (품목·수량·받을 센터)
        ▼
② 서버가 요청을 받음
        │   + 요청 시각을 한국시간으로 자동 생성
        ▼
③ 서버 → 슬랙 전용 통로(웹훅)로 메시지 전송
        │   (슬랙이 안 받으면 → 메일로 대신 발송)
        ▼
④ 담당자 슬랙 채널에 주문 메시지 도착 ✅
   📦 주문품목 / 품명 - 사이즈 - 수량EA / 받을 센터 / 요청일시
```

| ②③ 시각 붙여 슬랙 전송 | `server/server.js` | `/api/uniform-request` — KST 시각 생성 후 슬랙 웹훅으로 릴레이 |


### 5. 자주 나올 질문 (Q&A)
**Q. 슬랙이 잠깐 먹통이면 요청이 사라지나요?** → 아니요. 슬랙 전송이 실패하면 메일로 대신 보내도록 폴백을 뒀어요.
**Q. 요청 시각을 시공팀이 조작할 수 있나요?** → 없어요. 시각은 브라우저가 아니라 **서버가** 찍어요.

### 6. 핵심만 다시
- 요청은 **서버가 슬랙 전용 통로로 대신 전송** → 한 창구에 같은 형식으로 모임
- 요청 시각은 **서버가 한국시간으로 자동** → 오기입·시차 없음
- 슬랙 실패 시 **메일 폴백** → 요청이 사라지지 않음

## 🤔 고민 과정 (기록용)

**"두 번째 사용자를 어떻게 들일까"가 이 날의 큰 축이었다.** 관리자용 도구를 시공팀에게도 열어주고 싶은데, 그냥 같은 화면을 주면 실수로 원본을 건드리거나 단가가 노출된다. 그래서 처음부터 "**같은 데이터, 다른 화면·다른 권한**"으로 방향을 잡았다.

- **공개 화면을 따로 팔까, 관리자 화면에 권한만 나눌까?** → 따로 파는 쪽(`/request`)을 택했다. 시공팀은 "조회+요청"만 필요한데, 관리자 화면은 메뉴가 많아 오히려 헷갈리고 사고 위험이 크다. 화면을 분리하니 각자 목적에 맞게 단순해졌다.

- **단가, 화면에서만 숨길까?** → 안 된다고 판단. 화면에서 숨겨도 데이터가 브라우저에 오면 개발자 도구로 다 보인다. "숨기기"는 보안이 아니라 착시다. 그래서 **공개 API에서 단가를 아예 빼고**, 단가는 비번을 통과해야만 주는 별도 통로로 분리했다. 이게 이 날 가장 신경 쓴 설계다.

- **요청을 어디로 받을까 (메일 vs 슬랙)?** → 슬랙을 1순위로, 메일을 폴백으로. 담당자가 실시간으로 가장 빨리 보는 채널이 슬랙이라서. 대신 슬랙이 죽어도 요청이 사라지지 않게 메일 폴백을 남겼다.

- **센터를 자유 입력 두려다 드롭다운으로.** 자유 입력이 유연하긴 한데, "양지센터/양지/양지물류"처럼 표기가 갈리면 배송에서 혼선이 난다. 12개 고정 드롭다운으로 **표준화**하는 게 실무에선 더 낫다고 봤다.

- **왜 이 날 UI 통일까지 했나?** 기능만 붙이면 "관리자 화면 따로, 시공팀 화면 따로"인 두 앱처럼 보인다. 같은 서비스라는 느낌(초록 테마·LETUS 이름·탭 그룹화)이 있어야 사용자가 신뢰하고, 보고 자리에서도 "하나의 완성된 도구"로 보인다.

## 🛠️ 삽질 & 배운 점
- **슬랙 변수엔 서식(볼드)이 안 먹는다** — `{items}` 자리에 넣은 볼드가 무시됨. 서식이 필요한 문구는 앱이 아니라 **슬랙 워크플로 템플릿**에 둬야 한다. (그래서 `f96b411` → `ba9cf02`로 헤더를 템플릿으로 옮김)
- **워크플로 편집 중 변수가 지워지면 품목이 통째로 누락** — 이후 "알림에 센터까지만 오고 품목이 안 옴" 문제로 이어짐. 변수는 반드시 변수-삽입 버튼으로 다시 넣어야 함.

### ② 요청 → 슬랙 릴레이 (`server/server.js`)
요청 시각은 서버가 한국시간으로 생성해서 붙인다.
```js
app.post('/api/uniform-request', async (req, res) => {
  const { requester='', region='', center='', items='' } = req.body || {};
  const now = new Date(Date.now() + 9*3600*1000);           // KST
  const r = await fetch(SLACK_REQUEST_WEBHOOK, {            // 슬랙 웹훅으로 중계
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ date, requester, region, center, items })
  });
  if (!r.ok) throw new Error('slack ' + r.status);          // 실패 시 상위에서 메일 폴백
});
```
