## 🔍 깊게 보기 GitHub 주소로 들어가면 왜 404가 날까? (비전공자용 쉬운 설명)

저장소의 GitHub 주소로 들어가면 "404 page not found"가 떴어요. 고장 난 걸까요? 아니에요.

### 1. 한 줄 요약
이 앱은 **뒤에서 도는 서버와 DB**가 있어야 작동하는데, GitHub Pages는 **가만히 있는 파일만** 보여줄 수 있어요. 그래서 거기선 앱이 못 돌아 404가 난 거예요. 링크가 고장 난 게 아니라 **자리가 안 맞은** 거예요.

### 2. 왜 그럴까? (핵심 오해 풀기)
❌ **"링크가 깨졌나?"** — 아니에요. 주소는 멀쩡해요.
✅ **"그 자리에선 이 앱이 못 돈다"** — GitHub Pages는 **정적(가만히 있는) 사이트 전용**이라, 서버+DB가 필요한 이 앱은 원리상 실행이 안 돼요.

> **비유:** 전기밥솥(서버 필요한 앱)을 콘센트 없는 방(GitHub Pages)에 갖다 둔 셈이에요. 밥솥이 고장 난 게 아니라, 그 방엔 전기가 안 들어와요. 콘센트 있는 방(사내 서버)에 두면 잘 돌아가요.

### 3. 전체 흐름 (그림)

```
사용자 ──github.io 주소──▶ [GitHub Pages: 정적 파일만]
                                │  서버·DB가 없음
                                ▼
                              ❌ 404

해결(8/7):  그 자리에 '이정표 페이지'를 둠
   [GitHub Pages] ──안내 화면──▶ [버튼] ──▶ [실제 사내 서버(앱 작동)] ✅
```

### 4. 코드에서는 어디서 (파일별 역할)
| 단계 | 파일 | 하는 일 |
|---|---|---|
| 이정표 화면 | 루트 `index.html` | 사내 서버 주소(관리자 `/`, 시공팀 `/request`) 버튼 제공 |
| 앱엔 미포함 | `Dockerfile` | 이 안내 페이지는 실제 앱 이미지에 넣지 않음(순수 이정표) |

### 5. 자주 나올 질문 (Q&A)
**Q. 그냥 GitHub Pages에서 앱이 돌게 하면 안 되나요?** → 안 돼요. 서버+DB가 필요한 앱이라 정적 호스팅에선 원리상 불가예요.
**Q. 그럼 진짜 앱은 어디 있나요?** → 사내 서버(`uniform-stock.app2.hub.fursys.com`)에서 돌아요. 안내 페이지의 버튼이 거기로 데려다줘요.

### 6. 핵심만 다시
- 404는 고장이 아니라 **"그 자리에선 못 도는" 구조적 이유** (정적 vs 서버 필요)
- 잘못 들어온 사람을 **실제 사내 주소로 안내**하는 이정표를 둬서 혼선 제거

## 🤔 고민 과정 (기록용)
- "404를 없애자"보다 "**잘못 들어온 사람을 어디로 보낼까**"가 진짜 문제였다. 404 자체는 구조상 당연한 결과라, 그걸 숨기기보다 **올바른 곳으로 유도**하는 게 맞다고 봤다.
- 안내 페이지를 앱 본체에 넣을까 고민했지만, 그러면 실제 앱 이미지가 지저분해진다. 그래서 **순수 이정표로 분리**하고 Docker 이미지엔 넣지 않았다. "역할이 다른 건 섞지 않는다"는 판단.
- 이 문제는 [8/3 외부 호스팅 보류](2026-08-03_외부호스팅보류.md)로 접근성을 사내로 한정한 결정의 후속 정리이기도 하다.

## 💻 코드는 이렇게 구성했다 (기술 상세)

### 손댄 파일
| 파일 | 신규/수정 | 역할 |
|---|---|---|
| 루트 `index.html` | ✏️ 재작성 | GitHub Pages 접속 시 뜨는 안내(이정표) 페이지 |
| `Dockerfile` | (변경 없음) | 안내 페이지를 이미지에 넣지 않기 위한 근거 |

### 안내 페이지를 "앱과 분리"한 방법
- 루트 `index.html`은 **정적 안내 화면** — 사내 서버 주소(관리자 `/`, 시공팀 `/request`)로 가는 버튼만 있다.
- 이 파일은 GitHub Pages(정적 호스팅)에서만 보이면 된다.
- **핵심:** `Dockerfile`은 `public/`과 `server/`만 이미지에 복사한다. 루트 `index.html`은 복사 대상이 아니라서 **실제 앱(사내 서버)에는 포함되지 않는다.**
```dockerfile
# Dockerfile (발췌) — 앱 이미지에 담는 건 server/ 와 public/ 뿐
COPY server/server.js ./server/
COPY public ./public
# 루트 index.html(안내 페이지)은 복사하지 않음 → 앱엔 미포함
```
> 그래서 "GitHub에선 안내 페이지, 사내 서버에선 진짜 앱"이 깔끔하게 갈린다.
